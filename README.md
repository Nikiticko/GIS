# GIS Reports

Вебзастосунок для керування виробничими об’єктами. Вимоги описано в `PROJECT_SPEC.md`, карту проєкту — в `PROJECT_MAP.md`.

## Локальний запуск

Потрібні Node.js, npm і PostgreSQL. Налаштуйте `DATABASE_URL` у середовищі, потім виконайте:

```sh
npm ci
npm run db:migrate
npm run api:bootstrap-admin -- "Ім’я адміністратора" --show-code
npm run dev
```

Адміністратора створюють лише в порожній базі; код показується тільки в інтерактивному терміналі. Не зберігайте його в журналах.

## Підготовка до розгортання

`npm run build` збирає вебінтерфейс у `dist`, `npm run api:build` — сервер у `dist-api`. Для сервера доступні `npm run db:migrate:production`, `npm run api:bootstrap-admin:production` і `npm run api:start`. Вони запускаються з кореня проєкту. Перевірка доступності API та PostgreSQL: `GET /api/health`.

Вкладення зберігаються локально в каталозі `ATTACHMENTS_DIR` (типово `.local/attachments`). Обмеження активних вкладень одного об’єкта — 500 МіБ. Каталог і PostgreSQL необхідно резервувати разом.

HTTPS, запуск на VPS, автоматичне резервування на Google Drive і відновлення ще потребують налаштування та перевірки. Не використовуйте історичні демосхеми Supabase для робочої бази.

### VPS

Наведена конфігурація розрахована на Ubuntu з Docker Compose і каталогом проєкту `/opt/gis-reports`. Спрямуйте домен на VPS і відкрийте порти 80 та 443. Скопіюйте `deploy/production.env.example` у `.env` на сервері, задайте домен та однаковий випадковий пароль PostgreSQL в обох параметрах; спеціальні символи пароля в URL потрібно закодувати. Не публікуйте цей файл.

```sh
docker compose build
docker compose up -d db
docker compose run --rm api node dist-api/migrate.js
docker compose run --rm api node dist-api/bootstrap-admin.js "Ім’я адміністратора" --show-code
docker compose up -d
docker compose ps
```

Caddy отримує HTTPS-сертифікат для домену. PostgreSQL та API не відкриваються назовні. Журнали контейнерів обмежені трьома файлами по 10 МБ; перегляд: `docker compose logs`. Міграція, що вимагає адресу, не застосовується до старих записів із порожньою адресою без попереднього виправлення даних.

### Резервні копії

На VPS встановіть rclone та налаштуйте Google Drive, а поверх нього — **crypt remote** `gis-encrypted`. Скрипт довіряє цьому налаштуванню: прямий remote Google Drive не шифрує копії. Збережіть ключі шифрування окремо від VPS; без них відновлення неможливе. Налаштування rclone має бути доступне користувачу, від якого працює systemd-сервіс.

Скопіюйте `deploy/gis-backup.service` і `deploy/gis-backup.timer` до `/etc/systemd/system/`, перевірте шлях і назву remote, виконайте `systemctl daemon-reload` та `systemctl enable --now gis-backup.timer`. Таймер запускається о 03:00 за Києвом. Журнал: `journalctl -u gis-backup.service`. У ньому також записується вільне місце. Скрипт тимчасово зупиняє API, створює узгоджену копію БД і файлів, перевіряє завантажену копію та видаляє копії старші 30 днів. Тимчасові незашифровані файли створюються на диску VPS і видаляються після завершення; потрібне достатнє вільне місце.

Резервування та відновлення обов’язково перевірте на окремій порожній базі й окремому каталозі до роботи з важливими даними. Налаштування Google Drive, перевірка відновлення та фактичний запуск таймера ще не виконані.
